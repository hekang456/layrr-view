Git 集成：4种版本操作

src/server/version.ts 实现的安全版本管理

👁️ Preview 预览

git checkout <hash> --detach
→ 进入 detached HEAD 只读预览

↩️ Restore 恢复

git checkout <originalBranch>
→ 从预览态回到原始分支

⏪ Revert 回滚

git reset --hard <hash>
→ 永久回滚到指定版本

🚀 Commit 推送

git push -u origin HEAD
→ 推送当前 HEAD 到远程
⚡ 关键设计：preview/restore/revert 都是先发 WS 结果，再执行 Git。避免 checkout/reset 触发页面刷新导致消息丢失。

自动提交：精准追踪每轮修改

cli.ts editLoop 中的 Git 自动化逻辑
editLoop 执行流程：
1. 快照当前脏文件集合（git status）
2. buildPrompt() + agent.applyEdit()
3. 比较编辑前后文件变化
4. git add + git commit "[layrr] <instruction>"
5. notifyComplete() 通知前端
🎯 脏文件快照
记录编辑前后的脏文件集合，只提交 AI 本轮新增的改动，不误提交用户原本的本地变更
🏷️ 提交信息规范
[layrr] <用户指令摘要>，清晰区分 AI 提交与用户手写提交
� 启动时 Git 初始化：检查 git 仓库、创建 initial commit、如有未提交改动则创建 pre-layrr snapshot

Overlay 隔离：不污染宿主页面

overlay/ 目录下的运行时隔离机制
1
命名空间隔离
所有节点类名和 ID 都以 __layrr 为前缀，避免与宿主页面 CSS 冲突
2
样式主动注入
通过 styles.ts 注入完整 CSS，不依赖宿主页面提供任何样式基础
3
自身元素过滤
isOwn(el) 判断避免把工具栏按钮当作业务元素选中
4
Viewport 定位
高亮框基于 getBoundingClientRect()，不插入业务 DOM 层级
🔄 SPA 兼容：MutationObserver 监控根节点 + 监听 astro:after-swap / sveltekit:navigation-end / popstate 事件，路由切换后自动重建

数据流转：一次修改的完整旅程

🔄 从点击到修改完成的完整流程：
① 浏览器 → 用户点击，overlay.ts 捕获事件
② source.ts → 6种策略定位源码位置
③ WebSocket → PendingEditRequest 发送到后端
④ server/index.ts → 接收请求，进入 editLoop
⑤ source-mapper.ts → 验证路径，计算 sourceMatchQuality
⑥ prompt.ts → 根据 quality 构建差异化 Prompt
⑦ Agent → Claude/Codex 执行代码修改
⑧ version.ts → git commit 自动存档
⑨ WS 通知 → notifyComplete() 通知前端刷新
⑩ HMR → 页面热更新，显示修改效果

📦 PendingEditRequest

instruction, elementInfo, sourceLocation, sourceMatchQuality

✅ EditResult

success, message, commitHash, filesChanged[]

记住这 3 件事

1
点击即定位
从页面元素到源码行号，自动完成映射。多种策略逐级 fallback，总有一种能命中。
2
精度驱动 Prompt
定位准就给精简上下文，定位不准就补全更多信息。AI 拿到的永远是"刚好够用"的上下文。
3
零侵入 + 安全回退
不改你的源码，通过代理注入工具栏。每次修改自动 commit，改坏了随时回退。
